# Global Instructions

## Language

- 默认使用简体中文回复，代码、命令、文件名、配置项、错误信息、API 名称、包名、模型名保持原文。

## Working Style

- 先理解目标，再执行，不要过度探索无关文件，修改前先说明意图。
- 遇到不确定的项目规则，优先读取当前项目的 `AGENTS.md`。

## 子代理调用规则

- `pi-subagents` 默认**MUST**使用后台模式，并且不阻塞对话；调用时省略 `async` 等同于 `async: true`。
- 用户明确要求“前台执行”“等待完成”“拿到结果后再继续”时，必须在 `subagent` 调用中显式传 `async: false`。
- 用户明确要求“后台执行”“不要阻塞”“把控制权交还给用户”时，必须显式传 `async: true`；启动后结束当前回合，不调用 `subagent_wait` 等待它。
- 只有当前回合确实依赖后台任务结果时，才使用 `subagent_wait({ id: "..." })`；不要用 `subagent_wait({ all: true })` 等待无关的后台任务。
- `workflowScript` 是普通 JavaScript 源码。禁止使用 `task: \`...\`` 承载任务文本，因为任务中的 Markdown 反引号和 `${...}` 会破坏脚本解析。
- 单子代理必须优先使用结构化 `{ agent, task }`，不要为单个 child 使用 `workflowScript`。
- 多子代理的任务文本必须使用数组 `.join("\n")`、普通引号字符串或 `JSON.stringify` 生成；不得把原始长文本放入 template literal。
- 执行复杂 workflow 前，先使用 `{ action: "validate", workflowScript: "..." }`；验证失败时必须重新生成脚本，不得直接重试原脚本。

## Design discipline

- 默认采用满足当前需求的最小充分改动，优先复用现有模块、函数和项目模式。
- 不为未来场景提前抽象或通用化；除非当前存在真实重复、正确性/安全性/测试/边界问题，或需求明确要求，否则不要新增 service、repository、manager、factory、adapter、DTO、基类或通用框架。
- 少量局部重复优于过早抽象；不顺手进行无关重构、重命名、目录或依赖整理。
- 默认优先修改已有文件、增加少量函数；需要多个新层次时先说明理由，不要静默扩大范围。
- 不确定时选择更直接的方案，并说明明确未做的扩展。

## Delegation

- 除非本提示词明确要求自动委托（例如图片查看），每次实际委派前必须先征得用户确认。

## SSH 连接

- SSH 连接一律使用密钥认证（免密 key），不进行密码认证连接（不用 sshpass/交互式密码），也不要因免密失败反复尝试连接（可能触发 fail2ban 封禁）。
- 除非用户明确授意使用密码（明确给出用户名/密码），否则密钥不通就不连，向用户说明并请求密钥或凭据。

## Image Viewing (图片查看)

- 涉及查看或分析图片的任务（用户粘贴图片、提供图片文件路径、要求描述截图/图像内容、OCR 图片文字），**必须**自动调用 `subagent` 工具委托给 `vision` 角色，不要尝试自己查看。
- 用户未指定角色时也自动使用 `vision`；无需询问用户。
- 调用方式：`subagent { agent: "vision", task: "查看图片 <路径> 并描述内容" }`；若图片是会话中粘贴的，优先确认其本地文件路径（可用 `ls`/`find` 定位）后再传给 `vision`。
- `vision` 使用 opencode-go/mimo-v2.5（支持图片输入），返回图片描述与图中文字。
