# Global Instructions

## Language

- 默认使用简体中文回复。
- 代码、命令、文件名、配置项、错误信息、API 名称、包名、模型名保持原文。
- 技术解释尽量简洁，优先给可执行建议。
- 如果用户明确要求英文输出，则使用英文。

## Working Style

- 先理解目标，再执行。
- 不要过度探索无关文件。
- 修改代码前先说明意图。
- 遇到不确定的项目规则，优先读取当前项目的 `AGENTS.md`。
- 输出尽量直接、可执行。

## 后台子代理规则

- 将 `run_in_background: true` 视为异步执行：启动后台子代理后，主 Agent 应继续处理无依赖的主线工作，不要立即等待。
- 启动后台子代理后，不要立即调用 `get_subagent_result` 的 `wait: true`；优先依赖完成通知，或使用不阻塞的状态查询。
- 只有在子代理结果是下一步明确依赖时，才使用 `get_subagent_result({ wait: true })`。
- 进入截止时间收敛阶段时，使用 `steer_subagent` 通知运行中的子代理收敛，不要等待其结果。

## SSH 连接

- SSH 连接一律使用密钥认证（免密 key），不进行密码认证连接（不用 sshpass/交互式密码），也不要因免密失败反复尝试连接（可能触发 fail2ban 封禁）。
- 除非用户明确授意使用密码（明确给出用户名/密码），否则密钥不通就不连，向用户说明并请求密钥或凭据。

## Delegation (委托策略)

- 遇到需要深度探索、独立审查、并行调研或多步骤实现的任务，优先使用 `subagent` 工具委托给专门角色（scout/planner/reviewer/worker/context-builder），而不是自己包办。
- 委派标准：任务跨 2+ 个文件、需要第二意见/对抗性审查、需要网络调研 + 本地代码结合、或用户明确要求编排时，应委托。
- 单次轻量查询（如读一个文件、问一个简单问题）不必委托，直接处理。
- 委托时选择合适的角色，任务描述要具体、自包含（子代理看不到主对话）。

## Image Viewing (图片查看)

- 涉及查看或分析图片的任务（用户粘贴图片、提供图片文件路径、要求描述截图/图像内容、OCR 图片文字），**必须**自动调用 `subagent` 工具委托给 `vision` 角色，不要尝试自己查看。
- 用户未指定角色时也自动使用 `vision`；无需询问用户。
- 调用方式：`subagent { agent: "vision", task: "查看图片 <路径> 并描述内容" }`；若图片是会话中粘贴的，优先确认其本地文件路径（可用 `ls`/`find` 定位）后再传给 `vision`。
- `vision` 使用 opencode-go/mimo-v2.5（支持图片输入），返回图片描述与图中文字。
